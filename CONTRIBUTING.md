# Руководство для разработчиков

Спасибо за участие в развитии платформы студсовета СГН! Чтобы поддерживать порядок в коде, придерживайтесь простых правил ниже.

## 1. Работа с ветками
Прямые пуши в `main` запрещены — все изменения вносятся через **Pull Request**. Создавайте новую ветку от актуального `main`:
* `feat/<название>` — новый функционал (например, `feat/badge-export`)
* `fix/<название>` — исправление багов (например, `fix/login-rate-limit`)
* `refactor/<название>` — рефакторинг и тесты
* `docs/<название>` — обновление документации

## 2. Оформление коммитов
Используйте краткие и понятные сообщения (желательно в стиле Conventional Commits):
* `feat(events): добавить фильтр по дате`
* `fix(auth): исправить редирект после входа`
* `chore(deps): обновить пакеты фронтенда`

## 3. Проверка перед Pull Request
Перед отправкой PR убедитесь, что проект собирается и проходят тесты:
```bash
# Проверка сборки и unit-тестов backend
dotnet build
dotnet test StudentCouncil.Tests/StudentCouncil.Tests.csproj

# Проверка сборки frontend
cd StudentCouncil.Frontend
npm run build
```

## 4. Pull Request и ревью
* В описании PR кратко укажите, что сделано и как это проверить (для правок интерфейса приложите скриншот).
* Дождитесь прохождения автоматических проверок в GitHub Actions перед слиянием в `main`.
